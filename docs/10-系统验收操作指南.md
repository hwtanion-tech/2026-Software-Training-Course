项目在 G:\file\grade 4 first semester\PRACTICE\campus-news-system。准备两个PowerShell终端、浏览器、IDE和本指南。先在同一台机器提前下载依赖并启动成功；现场无需重新安装。JDK21、Maven3.9、Node20.19+或22.12+；MySQL模式需MySQL8.0.16+。

### MySQL验收模式

课程技术栈验收应展示MySQL模式及真实表数据。H2演示便于快速操作，不能把H2界面作为MySQL连接证据。两种模式使用独立数据，切换不会迁移内容。

初建时从database目录执行mysql -u root -p --default-character-set=utf8mb4，进入MySQL后执行 SOURCE schema.sql; 和 SHOW TABLES FROM campus_news;。创建或使用专用数据库账号campus_app，授予campus_news库的SELECT、INSERT、UPDATE、DELETE权限。已有表请先核对结构，不要删除已有库。

停止后端，在backend终端按下列方式启动；数据库和网站管理员密码是两种不同密码：

```powershell
$env:SPRING_PROFILES_ACTIVE='mysql'
$env:DB_USERNAME='campus_app'
$env:DB_URL='jdbc:mysql://127.0.0.1:3306/campus_news?serverTimezone=Asia/Shanghai'
$dbSecret=Read-Host '数据库密码' -AsSecureString
$env:DB_PASSWORD=[Net.NetworkCredential]::new('', $dbSecret).Password
$env:BOOTSTRAP_ENABLED='true'
$appSecret=Read-Host '首次网站管理员密码12至64位' -AsSecureString
$env:BOOTSTRAP_PASSWORD=[Net.NetworkCredential]::new('', $appSecret).Password
Remove-Variable dbSecret,appSecret
mvn spring-boot:run
```

仅sys_user为空时初始化admin；有用户时不会覆盖原密码。首次成功后停止后端，移除BOOTSTRAP_ENABLED和BOOTSTRAP_PASSWORD再正常启动。登录你自己设置的网站管理员，先新增分类及两个发布账号，再创建少量新闻/通知用于演示。MySQL模式不会自动创建表或演示账号。详细授权与清理环境变量步骤见项目docs/06。

## 2 现场演示顺序

开场可说：“这是校园新闻及通知发布系统，采用Spring Boot、Vue与MySQL。访客浏览公开内容，发布人员维护自己的内容，管理员维护全部内容、分类与账号。下面演示一条新闻从草稿到发布、撤回的完整流程。”根据当天实际运行模式说明当前数据库，避免混淆。

### 公开浏览约2分钟

不登录打开首页，展示最新新闻和通知；进入校园新闻，按标题关键词查询，再选择分类。清空条件后点击下一页，说明每页6条及总页数。点击一篇详情，指出标题、作者、分类、发布时间、摘要和正文；进入通知详情指出发布单位。

输入“验收不存在的关键词”查询，应显示0条和空状态。清空恢复列表。说明前台列表和详情都只允许PUBLISHED，不是只把草稿从页面隐藏。

### 新闻完整流程约4分钟

使用editor登录。新建标题为“第三周现场验收新闻”的新闻，选择一个启用分类，作者填写“韩文涛”，摘要填写“现场验收样例”，正文填写两段中文并保存。记下后台显示的ID。新建应为草稿；访问 /#/news/实际ID 提示内容不存在或未发布。

回后台点击发布，再点击查看，前台应立即可见。重新编辑标题加“已修改”并保存，应自动回草稿，原公开详情不可见；再次发布恢复。点击撤回，详情和公开列表都应隐藏。需要清理时只删除自己刚建的样例，删除后不能在页面恢复。

### 通知流程约1分钟

在通知管理新建“第三周实验室开放通知”，填写发布单位“实验中心”和正文，保存、发布、查看、撤回。通知没有新闻分类或作者输入，公开详情显示发布单位。

### 权限隔离约2分钟

记下editor创建的ID，退出改用other登录。other后台没有editor记录。说明后端即使收到直接请求他人ID也返回403，测试已覆盖；不要仅用“按钮没显示”作为权限证据。用admin登录后，应能同时看到不同创建者内容。

### 分类和账号约3分钟

管理员新增“现场验收分类”，修改排序并停用。在新闻编辑页应不能选择该停用分类，历史新闻仍保留分类名。停用不会自动撤回已发布新闻。

进入账号管理：新增账号teacher_demo（如重名则换一个账号），显示名称“验收发布人员”，角色发布人员，输入自行设置的12至64位密码。保存后可按账号或显示名称搜索；重新编辑时用户名不可改，密码留空保留原密码。

在另一个浏览器或不同浏览器配置中登录teacher_demo，保持其页面。回管理员界面停用teacher_demo，再让该用户请求后台，应被要求重新登录；重新启用也不能恢复旧会话。密码重设或角色变化同样要求重新登录。演示结束将测试账号停用保留，不要改动正在使用的admin、editor、other密码。

若现场只有一个浏览器配置，可以使用同机的另一个浏览器。普通同配置的两个标签共享Cookie，不能同时代表两个登录用户。密码修改由本人现场操作。

## 4 代码讲解与常见答辩问题

### 主要代码入口

- App.vue与AccountPage.vue：页面路由、管理入口、账号表单及请求。
- api.js：同源Cookie、CSRF、JSON、错误提示和超时。
- SecurityConfig：密码编码、登录认证、角色路径限制和会话注册。
- CurrentUser与ContentService：从登录身份取得创建者、所有权校验、状态转换和事务。
- AccountService：保护当前管理员、校验密码、保存账号并在事务提交后撤销旧会话。
- ContentRepository与UserRepository：参数化SQL、分页和创建者条件；数据库连接由Spring管理。
- database/schema.sql：四表、主外键、唯一性、状态约束和查询索引。
- ProjectApiTest：正常、异常、权限及会话撤销的28项测试。

后端Java路径统一位于backend/src/main/java/cn/edu/campus/news；前端位于frontend/src。建议现场打开ContentService的checkOwner、update、publish、withdraw和AccountService的update说明规则。

### 为什么使用前后端分层

Vue负责交互和展示，Controller接收参数，Service检查业务规则，Repository执行SQL。这样相同的发布和权限规则不会分散在不同页面中，也便于直接通过接口测试。

### 为什么发布人员不能伪造创建者

创建时由CurrentUser读取会话用户ID并写creator_id；请求模型没有可指定创建者的字段。修改、删除、发布和撤回时重新读取记录，比较creator_id，管理员可管理全部。

### 怎样确保撤回后真的不能查看

公开列表强制过滤PUBLISHED；公开详情也检查状态。撤回把状态改为WITHDRAWN，公开详情返回404，即使保留旧URL也不能读取正文。

### 为什么修改已发布内容回草稿

避免编辑过程中的未确认内容立即公开。修改保存后回DRAFT，编辑人员确认再发布；再次发布会更新发布时间。撤回则保留上次发布时间便于追溯。

### 怎么保存密码和防止旧权限继续使用

密码经过BCrypt编码后写库，接口不返回明文或哈希。账号状态、角色或密码改变时，SessionRegistry标记其已登录会话过期，下一次请求返回401。重新启用账号后仍需重新登录。当前实现面向单后端实例。

### 为什么不删除账号和分类

新闻引用用户和分类。账号通过停用保留历史创建者，分类通过停用保留历史分类信息，可避免外键断裂。普通新闻/通知支持在非发布状态下删除。

### 怎样处理SQL注入和正文HTML

SQL值使用参数绑定；动态表名仅来自news/notices枚举。搜索中的%、_和!按字面转义。正文按纯文本输出，Vue插值显示，不使用v-html执行用户内容。

### AI参与了哪些工作

应如实说明Codex辅助了需求与设计整理、较大范围代码生成、测试、问题修复和文档编写。工具执行的验证有记录；本人需亲自复验并能够解释核心代码，不能声称全部代码和测试由本人独立完成。

## 5 故障排查和提交核对

| 现场情况 | 处理方法 |
| --- | --- |
| 5173打不开 | 检查前端终端，确认npm.cmd run dev运行；端口占用时先停止旧进程 |
| 页面提示后端未启动 | 检查8080/api/health及后端日志；不要只刷新网页 |
| MySQL启动报错 | 核对实例、库名、用户名、密码与四表；确认mysql profile |
| 登录demo账号失败 | 确认当前是demo；MySQL使用自己初始化的管理员密码 |
| 写请求403 | 确认角色，刷新重新登录以更新CSRF；不要关闭CSRF保护 |
| 密码重设后被退出 | 这是预期行为，用新密码重新登录 |
| 新内容发布失败 | 核对标题、正文、作者/发布单位及启用分类 |
| 找不到此前demo数据 | 从同一个backend目录启动，核对.local路径 |

如需切回demo，停止后端后清理SPRING_PROFILES_ACTIVE、DB_URL、DB_USERNAME、DB_PASSWORD和BOOTSTRAP相关环境变量再启动。按Ctrl+C停止自己启动的两个服务。不要在现场重新导入整个数据库以“重置”问题。
